# 일상 생활 3D 시뮬레이터 MVP — 기획서

## 1. 개요

### 1.1 목적

웹 브라우저에서 **집(공간) + 캐릭터 + 하루 일정**을 3D로 시각화하는 **일상 생활 시뮬레이터 MVP**를 제공한다. 사용자는 미리 정의된 스케줄에 따라 캐릭터가 방을 이동하며 집안일·휴식 등을 수행하는 모습을 관찰하고, HUD로 현재 시간·활동·진행 상태를 확인한다.

### 1.2 대상 사용자

- 일상 루틴을 시각적으로 정리·공유하고 싶은 개인 사용자
- 3D 웹 데모·프로토타입을 빠르게 검증하려는 개발·기획자

### 1.3 MVP 범위 요약

| 영역 | MVP 포함 |
|------|----------|
| 집(3D 공간) | 단일 주택, 고정 방 레이아웃, 기본 가구/표면 |
| 캐릭터 | 단일 캐릭터, 외형 색상 샘플링(CharacterLook), 방 간 이동 |
| 스케줄 | 하루 타임라인, 앵커 시각·집안일(chores) 정의, 재생/일시정지 |
| HUD | 시각, 활동명, 재생 컨트롤, 간단 진행 표시 |

## 2. 기능 요구사항 (FR)

### FR-HOUSE — 집(공간)

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-HOUSE-01 | 단일 층 주택을 3D 씬으로 렌더링한다. | P0 |
| FR-HOUSE-02 | 방 구역을 명확히 구분한다(거실, 주방, 침실, 욕실 등 — 상세는 설계서). | P0 |
| FR-HOUSE-03 | 각 방에 **진입/체류 가능한 바닥 영역**과 **이동 목표 지점(waypoint)** 을 둔다. | P0 |
| FR-HOUSE-04 | 벽·바닥·기본 가구는 단순 메시/프리미티브로 표현한다(MVP). | P0 |
| FR-HOUSE-05 | 카메라는 orbit 또는 고정 각도에서 전체 집을 조망 가능해야 한다. | P1 |

### FR-CHAR — 캐릭터

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-CHAR-01 | 씬에 **단일 캐릭터** 1명을 표시한다. | P0 |
| FR-CHAR-02 | **CharacterLook**: 사용자 또는 프리셋 기반 **색상 샘플링**(피부/머리/의상 등)으로 외형을 구분한다. | P0 |
| FR-CHAR-03 | 스케줄에 따라 **지정 waypoint로 이동**하고, 해당 방에서 활동 애니메이션(또는 정지 포즈)을 보여준다. | P0 |
| FR-CHAR-04 | 이동 중 캐릭터는 바닥 높이에 맞게 Y축을 유지한다. | P0 |
| FR-CHAR-05 | 다중 캐릭터, IK, 리깅 고급 애니메이션은 MVP 제외. | — |

### FR-SCHED — 스케줄

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-SCHED-01 | **하루(00:00–24:00 또는 06:00–24:00)** 단위 타임라인을 데이터로 정의한다. | P0 |
| FR-SCHED-02 | 각 구간에 **시작 시각(앵커)**, **활동 ID**, **대상 방/waypoint**, **집안일(chore) 여부**를 연결한다. | P0 |
| FR-SCHED-03 | **재생**: 시뮬레이션 시각을 앞으로 진행시키며 캐릭터 상태를 갱신한다. | P0 |
| FR-SCHED-04 | **일시정지·재개** 및 **속도 배율(예: 1x, 4x)** 을 지원한다(MVP는 1x 필수). | P0/P1 |
| FR-SCHED-05 | 현재 구간 종료 시 다음 앵커 구간으로 자동 전환한다. | P0 |
| FR-SCHED-06 | 사용자 스케줄 편집 UI는 MVP 제외(JSON/코드 상수로 제공). | — |

### FR-HUD — HUD(헤드업 디스플레이)

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-HUD-01 | **시뮬레이션 시각**(예: 07:30)을 항상 표시한다. | P0 |
| FR-HUD-02 | **현재 활동명** 및 **현재 방/집안일 라벨**을 표시한다. | P0 |
| FR-HUD-03 | **재생 / 일시정지** 버튼을 제공한다. | P0 |
| FR-HUD-04 | 하루 대비 **진행률**(타임라인 바 또는 %)을 표시한다. | P1 |
| FR-HUD-05 | CharacterLook 색상 프리셋 선택(최소 2~3종)을 HUD 또는 사이드 패널에서 제공한다. | P1 |
| FR-HUD-06 | 3D 캔버스와 HUD는 겹치되, HUD는 HTML 오버레이로 구현한다. | P0 |

## 3. 범위 (In / Out)

### 3.1 In Scope (MVP 포함)

- Vite + React + TypeScript + React Three Fiber 기반 웹 앱
- 고정 레이아웃 단일 집, 정의된 방·waypoint
- 단일 캐릭터, CharacterLook 색상 샘플링
- 하드코딩/JSON 스케줄, 앵커·집안일(chores) 매핑
- 재생 상태 머신(idle / playing / paused)
- 기본 HUD(시각, 활동, 컨트롤, 진행)

### 3.2 Out of Scope (MVP 제외)

- 사용자 계정, 클라우드 저장, 멀티플레이
- 스케줄 CRUD UI, 드래그 앤 드롭 타임라인 편집
- 물리 엔진, 충돌, 문 개폐 애니메이션
- 고품질 캐릭터 모델·모션 캡처
- 모바일 터치 최적화(1차는 데스크푸 브라우저)
- 다국어(i18n) — UI는 한국어 우선, 코드 주석 혼용 가능
- 밤/낮 동적 조명 시스템(고정 조명만)

## 4. 성공 기준

### 4.1 기능 완료

1. 로컬 `npm run dev` 실행 후 브라우저에서 3D 집과 캐릭터가 **에러 없이** 표시된다.
2. 기본 스케줄 재생 시, **앵커 시각에 맞춰** 캐릭터가 해당 방 waypoint로 이동하고 HUD 활동명이 갱신된다.
3. **집안일(chore)** 로 태그된 구간에서 HUD 또는 활동명에 chore 구분이 표시된다.
4. 재생/일시정지 시 시뮬레이션 시각과 캐릭터 이동이 **일관되게** 멈추거나 재개된다.
5. CharacterLook 프리셋 변경 시 캐릭터 **색상/재질**이 즉시 반영된다.

### 4.2 품질·체험

- 초기 로드 후 **3초 이내** 상호작용 가능(로컬 개발 기준, 중간 사양 PC).
- 타임라인 끝(하루 종료)까지 재생해도 **메모리 누수·콘솔 에러 없음**.
- 기획 FR-HOUSE/CHAR/SCHED/HUD P0 항목 **100% 충족**.

### 4.3 산출물

- 본 기획서(`daily-life-sim.plan.md`) 및 설계서(`daily-life-sim.design.md`)와 구현 코드 정합성 유지.
- README에 실행 방법 1페이지 분량 기술(별도 작업).

## 5. 가정 및 제약

- 시뮬레이션 시각은 **실시간과 무관**한 가상 시계이다.
- 방 ID·waypoint ID는 설계서와 스케줄 데이터에서 **동일 키**를 사용한다.
- MVP 일정 데이터는 저장소 내 TypeScript/JSON 파일로 버전 관리한다.
